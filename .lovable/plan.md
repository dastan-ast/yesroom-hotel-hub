
# План реализации: Фильтры, улучшенная валидация и удаление бронирований

## Обзор задач

Пользователь запросил три улучшения:
1. **Предупреждение о конфликте дат** - при назначении номера на занятые даты выводить сообщение с именем гостя, который уже забронировал
2. **Удаление записей с подтверждением владельца** - возможность удалять бронирования (новые и закрытые), но только с подтверждением владельца
3. **Фильтры в модулях** - добавить фильтрацию по статусу в "Очередь бронирования" и "Шахматка", с автоматической приоритизацией активных заявок

---

## 1. Улучшенное предупреждение о конфликте дат

### Что сейчас:
- `RoomAssignDialog.tsx` отображает занятые номера серым цветом с пометкой "Занятые на эти даты"
- Нет информации о том, кто именно занял номер

### Что будет:
- При попытке выбрать занятый номер - показать toast с именем гостя и датами конфликтующей брони
- В списке занятых номеров отображать имя гостя рядом с номером комнаты
- Добавить tooltip с полной информацией о конфликтующей брони

### Изменяемые файлы:
- `src/components/admin/RoomAssignDialog.tsx`

---

## 2. Удаление бронирований с подтверждением владельца

### Логика:
- Добавить кнопку "Удалить" для всех записей (pending, approved, cancelled, checked_out)
- Для `checked_in` статуса удаление недоступно (сначала нужно выселить)
- Если пользователь - Owner (`isOwner`): удаление происходит сразу после подтверждения
- Если пользователь - Admin (`!isOwner`): показывается сообщение "Требуется подтверждение владельца"

### Сценарий для владельца:
1. Нажатие "Удалить" открывает AlertDialog с подтверждением
2. При подтверждении запись удаляется из БД
3. Если был назначен номер - статус номера обновляется на `available`

### Сценарий для админа (без прав владельца):
1. Нажатие "Удалить" показывает AlertDialog с пояснением
2. Вместо удаления - можно только "Отменить" (cancel) бронирование

### Изменяемые файлы:
- `src/components/admin/BookingsTab.tsx` - основная логика
- `src/components/admin/LiveFeedSidebar.tsx` - аналогичная логика для боковой панели

## 3. Фильтры в модулях

### 3.1 BookingsTab (Очередь бронирования)

**Добавляемые элементы:**
- Dropdown фильтр по статусу: "Все", "Ожидают подтверждения", "Подтверждено", "Заселён", "Выселен", "Отменено"
- Поиск по имени/телефону гостя
- Автоматическая сортировка: pending и approved первыми

**Логика сортировки:**
```text
1. pending (ожидают подтверждения)
2. approved (подтверждённые, ждут заселения)
3. checked_in (заселённые)
4. checked_out (выселенные)
5. cancelled (отменённые)
```

### 3.2 ShahmatkaGrid (Шахматка)

**Добавляемые элементы:**
- Фильтр по статусу бронирования для отображения: "Все", "Только активные" (pending, approved, checked_in)
- Кнопка "Показать все" / "Только активные"

**Изменяемые файлы:**
- `src/components/admin/BookingsTab.tsx`
- `src/components/admin/ShahmatkaGrid.tsx`

## Техническая реализация

### RoomAssignDialog.tsx - Информация о конфликте

```text
Изменения:
1. Расширить интерфейс Room для хранения информации о конфликтующей брони:
   - conflictGuestName: string
   - conflictCheckIn: string  
   - conflictCheckOut: string

2. В fetchAvailableRooms() получать данные о госте конфликтующей брони

3. При клике на занятый номер показывать toast:
   "Номер 101 занят: Иван Петров (15.02 - 18.02)"

4. В UI занятых номеров добавить имя гостя
```

### BookingsTab.tsx - Фильтры и удаление

```text
Новые state переменные:
- statusFilter: 'all' | BookingStatus
- searchQuery: string
- deleteDialogOpen: boolean
- bookingToDelete: Booking | null

Новые функции:
- handleDeleteWithConfirm(booking: Booking)
- confirmDelete() - удаляет запись из БД
- sortByPriority(bookings) - сортирует pending/approved вперёд

UI:
- Добавить Select для фильтра статуса рядом с кнопкой "Новое бронирование"
- Добавить Input для поиска
- Добавить кнопку "Удалить" (Trash2 icon) - видна только для owner
```

### ShahmatkaGrid.tsx - Фильтр активных

```text
Новые state переменные:
- showOnlyActive: boolean (default: true)

Логика фильтрации:
- Если showOnlyActive = true: показывать только pending, approved, checked_in
- Если false: показывать все статусы

UI:
- Добавить кнопку-toggle "Только активные" / "Все брони" рядом с навигацией
```

## Дополнительные примечания

- Удаление записей требует использования `useAuth()` для проверки `isOwner`
- При удалении брони нужно также удалить связанные записи из `booking_rooms` и `booking_services`
- Фильтры должны сохранять состояние при переключении между вкладками (опционально - через URL query params или локальный state)
- Все тексты на русском языке для консистентности UI
