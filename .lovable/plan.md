**Связи (триггеры):**
- `handle_booking_client` — при INSERT в bookings автоматически ищет/создаёт client и записывает `client_id`
- `validate_web_booking_date` — блокирует прошлые даты для web-бронирований
- `handle_new_user` — при регистрации создаёт profile + user_role='guest'

**Роли:** guest → admin → owner → superadmin. RLS через `has_role()` + `get_user_hotel_id()`.

## План оптимизации UX: минимум действий — максимум эффективности

### 1. Лиды: аналитика по умолчанию

**Проблема:** Аналитика скрыта за кнопкой, каждый раз надо кликать.

**Решение:** Вынести виджет аналитики источников (источники + UTM) в верхнюю часть LeadsTab — всегда видимый компактный блок с иконками и числами (как KPI-карточки в ExecutiveDashboard). Убрать кнопку-переключатель `showAnalytics`.

### 2. Объединение Бронирований + Шахматки в единый экран

**Проблема:** Сейчас "Бронирование" и "Шахматка" — два отдельных пункта меню. Админ постоянно переключается между ними.

**Решение:** Объединить в один пункт "Бронирования" с двумя режимами отображения:
- **Список** (текущий BookingsTab) — таблица с фильтрами по статусу
- **Сетка** (текущая ShahmatkaGrid) — визуальная шахматка

Переключение через ToggleGroup (иконки List/Grid) в заголовке. Один клик вместо навигации по меню. Убрать отдельный пункт "Шахматка" из sidebar.

```text
┌─────────────────────────────────────────────┐
│ Бронирования    [≡ Список] [⊞ Сетка] [+ ▼] │
├─────────────────────────────────────────────┤
│  (содержимое BookingsTab или ShahmatkaGrid) │
└─────────────────────────────────────────────┘
```

### 3. Дашборд: убрать дублирование, сделать action-oriented

**Проблема:** Дашборд показывает 3 KPI-карточки + кнопки навигации, которые дублируют sidebar. Нет actionable информации.

**Решение:**
- Заменить навигационные кнопки на **мини-шахматку на 3 дня** (сегодня + 2 дня) — мгновенный обзор заселений/выселений
- Добавить блок "Требует внимания": просроченные лиды (SLA), pending бронирования, overdue checkout
- Карточки KPI оставить, но сделать кликабельными (уже есть)

### 4. Sidebar: сокращение пунктов меню

**Текущие 16 пунктов** → **11 пунктов** после оптимизации:

Убрать:
- "Шахматка" (объединена с "Бронирования")
- "Справочник услуг" (переместить как вкладку внутри "Журнал услуг")
- "Журнал действий" (переместить внутрь KPI Админов)

### 5. Быстрые действия: один клик

- В шахматке: клик по пустой ячейке = создание брони с предзаполненной комнатой и датой (уже работает)
- В списке бронирований: swipe-actions или inline-кнопки "Заселить" / "Выселить" без открытия модалки для простых действий
- В лидах: кнопка "→ Бронь" прямо в строке списка, без открытия карточки лида

### 6. Технические оптимизации БД

- **Индексы:** Добавить составные индексы на `bookings(hotel_id, status, check_in_date)` и `leads(hotel_id, status, created_at)` для ускорения фильтрации
- **Дублирование логов:** `admin_activity_log` и `audit_logs` выполняют похожую функцию — рассмотреть объединение в одну таблицу с полем `log_type`
- **Clients ↔ Leads связь:** Добавить `client_id` в таблицу `leads` для прямой связи лида с клиентом после конвертации (сейчас связь только через booking)
